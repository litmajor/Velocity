# Security Disclosure Policy

We take security seriously. If you believe you've found a vulnerability in Velocity, please follow these guidelines.

1. Do NOT disclose the vulnerability publicly (issues, PRs, social media) until it has been evaluated and, if necessary, patched.

2. Preferred disclosure methods:
   - Use GitHub Security Advisories for this repository (recommended). This allows maintainers to discuss privately and coordinate a fix.
   - If GitHub Security Advisories are not available to you, open a private issue and mark it `security` and request maintainer contact.

3. What to include in your report:
   - A short, descriptive title.
   - Step-by-step reproduction instructions and minimal PoC code (if possible).
   - The impact and severity of the issue and any suggested mitigation.
   - Your contact information for follow-up.

4. Do not include sensitive data (secrets, private keys, or customer data) in your initial report; provide reproduction steps and a PoC that avoids leaking secrets.

5. Response and disclosure timeline:
   - We will acknowledge receipt within a few business days.
   - We aim to triage and respond with remediation guidance within 14 days.
   - Coordinated public disclosure will be agreed upon with the reporter.

6. Credit: If you request credit for a responsibly reported issue and it is fixed, we will credit you in release notes unless you request anonymity.

Thank you for helping to keep Velocity secure.
